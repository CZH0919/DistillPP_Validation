## 2. 复用结论及证据等级

1. **文件身份与完整字节校验已通过。**24 项、97,622,507,653 bytes（约 90.918 GiB）；15 项大文件及 9 项小文件全部按清单哈希核对，使用低 CPU/空闲 I/O 优先级顺序读取，命令退出 0。报告：`resource_check_20261016_091241_1370827.json`。这一步没有下载网络内容或写共享权重。
2. **源码事实。**固定 LightX2V 的 `WanDistillModel._load_ckpt` 明确支持现有 `distill_model.pt`，不需要为换后缀重下。官方 Diffusers v0.35.1 的 T2V-14B 转换是所列参数名映射，`TRANSFORMER_SPECIAL_KEYS_REMAP={}`。来源链接列在下方。
3. **结构核查实测。**原生 Wan meta 模型、现有 BF16 学生 PT 与已有 F32 教师 12 个分片均为 1,095 个键；官方规则映射无碰撞、覆盖完整、形状全部匹配。学生通过 weights_only + mmap + meta 读取结构，没有分配整份真实模型张量。
4. **有限字节抽查。**误下载教师第一分片中的 189 个张量各取起止最多 64 bytes，共 24,192 bytes/份，对照现有 Diffusers 教师，全部相同。该抽查不能证明全部张量等价；完整文件哈希证明各自对应所固定的官方文件。
5. **仍未验证。**教师读取现有分片并映射为原生 Wan 的真实加载入口尚待 S1 实现；加载、前向、六指标、性能与教师质量优势均未运行。现有原版学生 PT 已作为本批固定身份，不宣称与另一仓库 safetensors 逐张量等价。

结构报告：`model_layout_audit.json`；核查代码与官方重命名规则位于 Project_Plan。初次直接 import wan 命中了 T5 模块默认参数里的 CUDA 查询，在隐藏 GPU 的上下文退出 1；已改为只加载所需模型模块、显式禁止 CUDA 初始化，最终退出 0、`cuda_initialized=false`。没有启动 GPU 推理或计算实验。

因此当前生成模型新增下载为 **0 bytes**，不需要创建另一份约 57 GB 的转换权重。加载层适配只在内存中改参数名/所需 dtype，继续保留原生教师的前向和采样协议。

## 3. 预防再发生的实际修改

- 清单 v2：模型条目指向两个已有仓库，强制 reuse-only；删除旧新建教师/新学生的下载对象。
- 下载器：模型缺项、哈希不符就报错，禁止创建目录、链接、下载或覆盖；只有项目内的评测条目允许下载。已有文件先验证后跳过，下载使用固定 revision/哈希和可续传临时文件。
- 四项回归检查在目标 Linux 通过：缺失模型不能触发网络或建目录；不符文件保留；已有模型只读校验；模拟评测下载后重跑不再次下载。测试只写项目临时目录的三个字节，无真实网络/GPU。Windows 沙箱不允许 hardlink，实际发布操作在 Linux 通过验证。
- 清理脚本默认预览，`--apply` 才执行；限定六个已记录对象、严格核对身份和空闲状态，逐项 unlink，最后 rmdir 空目录。文件增加/改变/占用则停止，不递归清理，不触碰 VAE 原件。目标服务器 fuser 不接受独立 `--`，已按固定绝对路径调用修正。
- 实验计划、基线路径、下载说明、总体进度已统一到复用路径。此前取消 dynamic_degree 数值容许界、使用 50/4 与真实耗时的修订保持。
- 通用手册仅增加下载前的“盘点—身份—兼容—复用/缺失—增量预算”规则；仍仅保留本地/远端各一份最新版，不记录事件历史或创建时间。
