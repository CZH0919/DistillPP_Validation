# 官方依据对齐的教师资格筛查 V2

状态：**S2-R 已执行完成并通过完整性复核；五质量指标 0/5 建立教师优势，资格未通过；S3 未开始。**结果与解读见 `../Result/S2R_20261017/REVIEW_AND_INTERPRETATION.md`。机器可读定义及全部原文见 `QUALIFICATION_V2.json`；该文件及其生成前状态字段保持冻结，当前进度另记。按用户确认：每库 16 条 prompt，每条 3 seeds，只评测所属库的三项指标；资格通过并获准迁移后沿用同一面板，不新增或扩大 prompt/seed。旧 S2 数据独立保留。

## 1. 唯一研究主线与当前顺序

寻找能够在有科学意义的目标质量维度上建立原始多步教师优势的模型组合，然后检验 Distillation++ 的有限推理纠偏策略迁移到真正蒸馏的双向少步扩散/Flow Matching 视频模型是否有效：相对学生提高质量，相对完整教师保留真实速度优势。

当前按“权重与生成调用核查 → 对齐有官方依据的 prompt/指标 → 新的配对资格验证 → 研究者确认后迁移”推进。核查服务于可信的基线，不扩展成权重验证研究；不因资格阴性就假定实现错误，也不把研究转为更弱教师的局部价值。

## 2. 权重与调用核查结论

证据：`Project_Progress/Stage_Progress/BASELINE_AND_PROMPT_REVIEW_20261017.json` 与 `BASELINE_CONTRACT_CONCLUSION_20261017.json`。

- 24 项生成资源的既有完整哈希与官方资源清单相符；本轮远端大小/mtime 均未变化。此次没有重新读完全部权重计算哈希。
- 实际运行脚本、原生核心源码与本地审查文件相符；教师有序键映射与官方 Diffusers 转换表完全一致。
- 核对 96 条成功生成记录、48 对共同噪声/正向条件、7 份成功 worker 加载记录：教师完整加载 1095 键、无缺项，50 步/100 次分支预测；学生为完整双向四步蒸馏 PT、1095 键、4 次预测、关闭 CFG。所有有效样本的时间表一致。

## 3. 哪些设置需要修正

旧六指标定义本身有官方来源，现有分数也没有被发现算错。主要不足在于用一个混合小面板统一估计所有维度：16 条中 8 条源自 human_action，只有 4 条来自时序组、4 条来自成像/美学/语义组。旧结果仍是其固定协议下的有效观察，不能当作全面能力排序。

V2 在项目层面保留全部六指标，每条视频只计算所属任务库的三项。采用固定 VBench 的两套官方任务库，并使用 VBench 团队公开的 Wan 扩写文本作为两组相同的生成输入。

| 官方任务库 | 完整条目数 | 初筛条目数 | 正式主统计对应指标 |
|---|---:|---:|---|
| subject_consistency（主体与运动库，`motion`） | 72 | 16 | subject_consistency、motion_smoothness、dynamic_degree（护栏） |
| overall_consistency（成像与语义库，`visual_semantic`） | 93 | 16 | imaging_quality、aesthetic_quality、overall_consistency |

**每条成片只计算并保留上表指定的三项，不额外计算另一库指标作为诊断。**未分配的指标标记为“不适用”，不算缺失、不填补；三项应测指标全部有效才算该视频评测完整。dynamic_degree 只监测主体与运动库，不能据此声称成像与语义库的视频运动也保持不变。不混合两库分数制造总体质量平均，不新增人工评分、动作专项指标或其他评测权重。

官方集合与采样规则来自 [VBench prompt 协议](https://github.com/Vchitect/VBench/blob/fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490/prompts/README.md)。完整库 165 条含两条仅大小写不同的语义锚点，清单保存原条目，初筛按规范化锚点去重，避免伪重复。

## 4. 已整理的输入与采样规模

- 正式候选库为官方 72+93 条；原文、公开扩写、源索引、所属指标、文本 SHA 来源及长度检查均写入 JSON。
- 初筛排除旧 S2 已使用的所有语义锚点。按 `SHA256(固定命名空间/规范化原文)` 排序，各集合取前 16 个不同锚点，不读取结果分数用于选择。共 32 条 prompt，均未用于旧 S2；此次从已准备的每库 24 条中按原排序取前 16 条，未重抽样或改写文本。
- 3 个新 seed 在生成前由固定命名空间的 SHA-256 推得：`1529987743`、`1993624635`、`1454077509`。两组每对共用实际初始噪声和同一扩写文本。
- 初筛为 **32×3×2 = 192 条视频、576 个指标值**。每项指标来自对应库的 16 条 prompt×3 seeds×2 组，即 96 个视频值、48 个配对差，独立 prompt 簇为 16 个。
- JSON 的 165 条原文是来源清单；只有 `screen_selected=true` 的 32 条及 `screen.active_prompt_ids_by_domain` 是活动输入。完整原文、公开扩写、所属指标及 seeds 共同形成 `screen.active_panel_sha256`；迁移配置引用同一指纹。
- 官方完整参考为 165 条×5 seeds×2 组=1650 条视频，**仅作协议背景，不安排扩展执行**。本次每库 16×3 是缩小的配对筛查，不称官方排行榜复现。

每指标 16 个 prompt 簇不构成功效保证；区间跨零如实记为不确定。没有建立优势时不得依据结果追加 seeds、替换文本或扩大面板直到通过。后续迁移使用同一输入配置，具体约定见第 8 节。

## 5. 条件与评分文本分别管理

生成采用[公开 Wan 扩写](https://github.com/Vchitect/VBench/blob/fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490/prompts/augmented_prompts/Wan2.1-T2V-1.3B/all_dimension_aug_wanx_seed42.txt)，逐条按索引对应原文，不临时调用 LLM，不购买/下载扩写模型。两组接受完全相同的文本。该文件虽位于 1.3B 命名目录，官方 14B 的 2025-07-25 [生成记录](https://github.com/Vchitect/VBench/blob/fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490/sampled_videos/README.md)也直接引用它。长文本不保证更好，作用方向属于待实测问题。

ViCLIP 的评分语义锚点使用原始任务文本，避免把生成时增加的风格/背景当成另一项评测目标。不能把约百词扩写直接传入 32-token 编码器，再宣称评估了完整扩写。

本轮仅在 CPU 用现有词表检查：全部 165 条生成文本的 T5 最长为 304 tokens，没有超过 512。官方原文 `VB0699`、`VB0724` 超过 ViCLIP 的 32-token 上限；本次初筛包含 `VB0724`。为保持官方实现，V2 明确沿用其原生 32-token 截断规则，保存完整原文、截断标记、实际有效 token 哈希；同时预先约定另报无截断子集作为敏感性描述，不取代完整主统计。这里是公开记录的评测器限制，不改写原文、不静默丢弃条目。V1 对短文本的禁止截断断言不能直接套用到 V2；该差异须在新评分适配器中明确验收。

## 6. 保留模型原生设置，说明与官方榜单的距离

使用已有教师/学生/评测资源，保持当前 832×480、81 帧、16 FPS、T50 原生 UniPC/CFG=5/shift=5、S4 固定步表/shift=5/CFG 关闭、FA2、原生混合精度、共同 T5/VAE。原生 Wan T2V 默认 shift=5；README Diffusers 的 480P 示例建议 3，是不同建议口径，尚无本项目证据证明更换后会恢复优势。不为使结果符合预期同步更改多个变量。

当前学生固定官方示例是 480P；不能仅为接近教师榜单而默认把该蒸馏 checkpoint 升至 720P。官方后期 14B 记录是 720P，本次是 480P、子集、3 seeds，因此只主张**prompt 来源及指标对应关系有官方依据**，不能与公开排行榜总分直接比较。

“highest quality”所在[格式说明](https://lightx2v-en.readthedocs.io/en/latest/getting_started/model_structure.html)没有给出当前 T50 与此 S4 PT 的定量质量对照。不能把“使用官方评测方法”写成“官方已经保证这一组合教师更强”。教师优势仍须本项目实测建立。

## 7. 判定、成本与下一执行边界

每个指标在指定任务库中计算同 prompt/seed 的 T−S 差，再平均 seeds、等权平均 prompt；按 prompt 簇 bootstrap 10000 次，带上同一 prompt 的两组与三个 seeds。五质量比较族继续用逐项 99% 区间，dynamic_degree 用 95% 区间。保留固定目标顺序 `imaging_quality → subject_consistency → overall_consistency → aesthetic_quality → motion_smoothness`。

至少一项预设质量指标区间下界大于零，才报告候选教师优势；实际意义和其余指标的取舍由研究者判断。动态程度继续仅作运动护栏，不设可接受降幅，不作为越高越好的质量指标。全部结果和失败完整披露，不与旧 S2 混池，不把跨零等同于等效。发现候选后由研究者确认目标及是否进入 Distillation++ 迁移。

由旧 S2 中位数估计，192 条的纯去噪+VAE 总量约 **14.06 GPU 小时**，未含加载、预热、文本、导出和评测；这不是完工时限。运行前仍须实时检查空闲 GPU、磁盘和内存，只使用无他人驻留进程的卡。

新批次已按冻结的 32 条 prompt、生成/评分文本分离、每条仅三项指标、token 元数据与面板指纹完成完整预热、192 条正式生成及 576 项评分，验收与本地复算通过。预设教师优势判据未通过；完整结果见 `../Result/S2R_20261017/`，当前进度见 `../Project_Progress/Total_Progress.md`。旧 S2 脚本与结果冻结保留；未新增模型或评测权重，未进入 S3。

## 8. 资格通过后的同面板迁移约定

教师优势建立、研究者确认目标并授权 S3 后，S3/S4 均引用当前 32 条 prompt、相同公开扩写/评分原文、库与指标对应关系、三个 seeds 和逐对实际初始噪声。**不另建开发 prompt，不新增独立确认 prompt，不扩大面板。**这能保持比较条件和复用已有证据；固定 prompt 本身不保证重新生成时仍有教师优势。

- S3 接口控制和有限 λ 选择仅取本面板固定子集：各库按既有排序前两条，即 `VB0309`、`VB0273`、`VB0761`、`VB0713`，各用前两个既定 seeds。共 4 prompts×2 seeds；没有新文本或新 seed。每条仍只评测所属库三项，目标增益只在目标指标对应库计算。
- S4 在完整同一面板比较 T50、S4、S4_T1：**32×3×3 = 288 条比较视频、864 个指标值**。配置、输入噪声/条件、视频与评分身份一致时，复用资格阶段的 192 条基线视频和 576 个分数，最终比较只需补齐至 96 条纠偏视频、288 个分数；已经生成且配置完全一致的选中候选也可复用。S3 控制、未选中候选、预热和重试单独计成本，不能把 96 条写成整个迁移阶段总生成上限。
- 逐指标报告配对差、全部样本及按 prompt 簇计算的描述性 95% 区间，同时报告真实耗时和运动变化；不设置动态比例容许界。输入、模型驻留及计时条件不一致时先核查影响，必要的耗时复测也使用同一面板输入。
- 目标选择和 λ 选择使用了本面板，因此最终结果是**同面板迁移效果验证**，不称独立确认或未见 prompt 的泛化验证；常规区间没有计入选择过程，不能宣称独立确认性的标称覆盖率。复用 T50/S4 只引用原资格证据，不重复计为一次独立教师优势验证。完整呈现各候选与全部六维对应结果，由研究者判断实际增益和取舍。
